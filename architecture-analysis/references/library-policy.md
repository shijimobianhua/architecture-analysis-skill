# 六类经验库与规则迭代

## 存储与兼容
库是可写本地数据，不是智能体的记忆或技能指令。默认 `~/.workbuddy/architecture-analysis-library`，可由用户指定其他位置；存在旧版 `~/.codex/architecture-analysis-library` 且新路径未建立时沿用旧库，不自动搬迁。安装/升级不能覆盖库。

随技能发布的 references/methods-*.md 方法卡是可选说明，不是用户经验库条目，也不表示其出图效果已经通过真实订单验证。不得因参考外部流程就自动收录其模板、图片或客户素材；当前任务优先且条件匹配才使用。2.2.0不迁移库、不更改检索算法和授权状态。

保留V1的index.json、styles/、拒绝记录、参考与客户授权状态；scripts/style_library.py继续兼容旧风格卡。V2新增experience-index.json及experiences/，不重写旧索引。当前任务可语义匹配旧风格和新经验，V2新增内容走统一评审，不按两个库分别询问。

## 候选与一次性确认
覆盖brief-interpretation、style-adaptation、general-diagram、plan-diagram、model-diagram、layer-delivery六类。每条候选记录适用范围、问题、解决方法、材料依据、反馈及验证结果，并区分project_specific、conditional、general_rule。

先分别评估内容理解、风格、文字可读性、几何、分层交付，成功导出不能证明全部正确。未经收录同意，候选只留在本单内部记录。新风格或已有类别有实质新改进才形成候选；重复无新信息不问；有实质反馈或验证状态改善时可以形成新修订候选，单纯新增调用次数或新案例文件名不算改进。

评审后集中展示编号清单，一次询问“全部收录、选择条目收录、不收录”，等待明确决定。同意当前更新计划不授权自动收录未来客户材料。客户参考/项目截图需要单独允许；先去掉身份与机密，无法去除则不复制。拒绝记录抑制同候选再问；用户主动要求重新处理时使用明确的新修订订单ID，不暗中重开同单确认。

## 检索不形成路径依赖
优先级：当前明确指令和参考 > 本单事实 > 条件匹配且有效的经验。scope可限定图种、项目类型、风格标签、约束与项目ID。任一限定不匹配或当前信息不足时不直接套用；仅作为待验证候选，不修改任务。

只读少量命中记录。按适用条件与验证结果排序，不使用次数、流行度、最近连续风格或自动推断偏好。项目特例仅匹配该项目；风格A的经验不能因高频进入风格B。旧卡语义检索遵循同一原则，不能让精确指纹或脚本替代判断。

## 规则晋升与撤回
普通经验入库不自动改写SKILL.md。通用规则候选必须在确认清单单独列出，用户明确允许规则更新；至少两次适用场景复现并通过跨风格/图种回归后，才可标记validated，并提出具体规则改动。脚本promote只改变经验状态，不会修改已安装技能。

实际技能规则修订需保存旧版本、改动原因、适用范围和回归结果，再同步项目/安装包/已安装版。一次项目的颜色、人数、布局不得晋升为普遍限制。负反馈涉及已收录处理时，在同一确认清单里提出撤回或缩小适用范围，不能继续套用已发现错误的旧经验。撤回保留历史和原因，撤回项不再检索。过去的客户授权不可因撤回或升级而扩大。

## 工具
"${CODEBUDDY_SKILL_DIR}/scripts/experience_library.py" --library LIB status batch.json：只读是否有新候选、该单是否已评审。
review batch.json --accept a b --approved：仅收录所选，其余记录拒绝；--accept不带ID表示全部不收录。--approved必须对应用户本次明确决定，不可自行填写。重复同一决定幂等，变更需明确新修订ID。
query context.json：只读有效且适用的少量条目；未验证、失败、撤回和未晋升的通用候选不作为可直接套用的经验返回。
revoke ID --reason 原因 --approved：保留历史并撤回。
promote ID --regression report.json --approved：须有passed、reproductions>=2、cases；只标记验证，不编辑技能。
