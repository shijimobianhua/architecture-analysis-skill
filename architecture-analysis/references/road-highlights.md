# 道路连续高亮与场地标记 · 3.2

仅在区位/场地要强调道路时读取；不改变其他图种、当前参考、字体、配色或密度。底图路网提供低权重地理背景，道路高亮强调选定路段，到达箭头表达有依据的方向，场地标记指出项目位置/范围；四者不混用。

## 选择和连续表达

按本图问题选择与场地相关的道路，不把全部可见路网染成点缀色、不为丰富度增加红线。内部已有视觉方案中引用每条选中道路/组件的对象、选择理由、材料和完整起终范围；分析强调等级不冒充行政道路等级。优先复用可靠地图几何或客户资料；只有栅格时核对后描绘，不从卫星图猜道路或新增路网调查。

无特别参考默认连续路幅色带：有真实道路边界则依轮廓填色，只有中心线则用单条连续粗实线，不默认分别描道路两侧、中央分隔和逐车道叠线。表达线宽不能当真实道路宽度。原图确为双幅、匝道或本图确需分向表达时按依据分开，不能为减少线条虚构中间也可通行。当前参考/明确要求可覆盖默认方法，不固定红色和线宽。

覆盖选定路段在本图显示范围内的完整部分。可结束于画幅边缘、真实道路端点、明确分析节点或有依据的研究范围；材料分段、转弯难描、标签遮挡、制作时间不构成断线理由。仅分析一段时先明确该段范围；不要无解释地画一半漏一半。源数据自身是否已覆盖完整所选范围需核对，工具无法从输入猜遗漏的真实道路。

将同一连续组件的分段按次序整理，排除重复；路口/弯道检查接续、接缝、宽度变化及叠色。路名优先移位或沿道路组织，不为了标签切断高亮。道路应延伸到显示范围外再裁切，不为满足一般line操作的越界检查提前终止。实线道路与方向箭头分层规划，不能把装饰箭头当道路补段。

高架、地面、隧道、匝道保持真实关系，不根据画面相交推断可转向。不同高程/分支作为独立组件，不跨组件吸附或造连接。必要的桥上桥下视觉分离依材料和当前配色处理；如需新增颜色仍先获同意，不默认加白色套线。

## 场地与底图主次

场地位置可用清楚的圆点/定位环；可靠边界可用轮廓和半透明面。让场地易于从道路和普通设施中辨认，具体主次服从本图主题，不重复堆圈/光晕/色块。只有点位时不能涂整块街区当用地；定位环不代表用地红线、距离圈或尺度。旧分层工具即可绘制这些符号，必须与道路和底图共坐标。原图复杂时降低非重点底图元素的对比，保留关键几何与来源信息，不以AI重画真实地图。

## 轻量覆盖层工具

`"${CODEBUDDY_SKILL_DIR}/scripts/road_overlay.py"`使用Python与Pillow，不新增GIS引擎、网络服务、Agent或客户必填字段。输入是已核对的内部sidecar schema 1.0，原订单/图层/经验schema继续2.0。每条road记录代表一个已选连续、不分叉组件；分支、不同高程、双幅等可分别记录，是否需要分别强调由内容方案决定。

```text
python "${CODEBUDDY_SKILL_DIR}/scripts/road_overlay.py" check internal/roads.json --out internal/roads-check-v1.json
python "${CODEBUDDY_SKILL_DIR}/scripts/road_overlay.py" render internal/roads.json --out internal/roads-v1
```

正常制作只需render一次，内部先检查再绘制；check用于预检或排错，不要求每单重复执行两遍。输出完整画布RGBA roads.png与内部report.json；将roads.png以source放进现有分析线条层，再用原工具合成完整PNG。报告留内部，客户包不默认包含源几何。异常只修道路层及关联标签/图例，不重生无关素材，不启动PS。

```json
{
  "schema_version":"1.0",
  "canvas":{"width":1200,"height":800,"dpi":300},
  "viewport":[0,0,1200,800],"coordinate_space":"source_pixels",
  "transform":[1,0,0,1,0,0],"antialias":2,"join_tolerance_px":0.5,
  "styles":{"primary":{"color":"#B83030","width_px":14}},
  "roads":[{"id":"road-a","label":"道路A","reason":"本图重点联系","evidence":"已核对几何记录",
    "geometry_type":"centerline","style":"primary","structure":"ground","z_order":0,
    "segments":[{"id":"a1","points":[[-20,300],[500,350]]},{"id":"a2","points":[[500,350],[1220,400]]}],
    "ends":{"start":{"kind":"frame"},"end":{"kind":"frame"}}}]
}
```

示例为虚构语法，不是当前项目或默认版式/路数/线宽。viewport为最终像素整数矩形，transform为[a,b,c,d,tx,ty]，x'=ax+cy+tx、y'=bx+dy+ty。coordinate_space支持source_pixels/final_pixels，或明确crs为EPSG:3857/GCJ02:WebMercator的map_projected；不直接接受经纬度，不自动转换坐标系。变换必须与地图共用，不能将投影转换正确等同于地图已贴合。

中心线segments按选定路径顺序提供，工具可反转单段方向以接续，不跨组件或路口寻找新路。默认绘制所有参考分段；可显式draw_segments列出ID，用于核对选段/改稿，但相对本条记录的参考范围遗漏、重复、未知ID都会报错，不静默交付缺段图。若要改变分析范围，应核对后另存新的参考范围与终点依据。相同参考几何反向重复也报错；几何等价检测不是完整GIS去重。

端点kind为frame/road_end/analysis_node/study_limit；后三者附evidence。frame端点应在显示边界或其外，不能在图中间声称到边缘。默认0.5px接续容差仅处理取整差异，小于等于容差会记录吸附；超过容差报断口，不拉长容差掩盖缺段。

路幅面使用geometry_type=surface，每段为`{"id":"p1","rings":[外轮廓点数组,可选孔洞点数组]}`；width_px不参与真实路幅形状。可附已核对axis点数组用于起终范围检查，没有axis时不要求伪造中心线，连续性/终点保留人工检查。面分段共享边缘与孔洞仍需看原图；工具只确保所有登记分段被画出，不证明任意面段已经无缝相连。

z_order用于已知层次，structure为ground/bridge/tunnel/unknown；非默认层次/构造需structure_evidence。不同组件仅按声明顺序绘制，不建立路网连接。相交异高程中心线会记录独立性并提示视觉检查；需要时可为中心线样式明确指定casing_width_px和casing_color以显示上跨关系，不能默认白套线，面轮廓的套线暂不支持。套线只是绘图表达，不证明高程。

同一层次/样式合并遮罩后一次上色，分段接头用圆滑连接，不逐段alpha叠加。所有样式使用同一透明画布及坐标；先绘制完整路径再裁到viewport。抗锯齿默认2倍内部栅格后回到原始尺寸，不改变最终画幅；高分辨率像素预算64M，超限需明确降低内部antialias，不缩画布。PPI跟随最终交付，颜色/透明度直接落实像素。旧compose的普通线条越界规则不改。

## 验收边界

样式可设置整数priority表示本图分析强调先后，默认0；同一z_order中较高priority后绘制，不能靠样式名字的排序决定主次。它不是道路行政等级。z_order按已知高程关系优先，二者不混用。半透明相交区域使用覆盖遮罩而非反复alpha叠加，最终仍需看实际地图上的可读性。

先沿每条选中道路从起点到终点检查连续、贴合、转弯、交叉和可读性，再看场地/道路/设施/底图主次，最后做既有PNG复原。结构化工具能发现已登记参考分段遗漏/重复、中心线接续缺口及不合理终止；只有栅格或面段缺辅助轴时实际看图检查，不只核几个点就填通过。

报告的checks_complete_review_required不代表地理核验、面连续性、桥梁视觉分离或客户成图通过。提供的参考本身漏了道路，工具也可能技术通过；不得将它描述为自动验证真实全路网。普通订单只读本图需要的说明、只做必要一套覆盖层，不逐单做测试图或新增调查。经验仍按本单一次授权收录。
